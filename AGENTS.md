# Working on kelson as an agent

Read [CONTRIBUTING.md](CONTRIBUTING.md) first — it covers code style, the renderer-purity rule,
testing and commit conventions, and applies to you unchanged. This file covers what CONTRIBUTING
doesn't: where things live, how parallel agents share the repo, and the mistakes this project has
actually made.

## Source of truth for project state

**GitHub issues and milestones, not the prose in this repo.** README.md and CONTRIBUTING.md describe
the project's intent and lag behind the code. To find out what is actually built:

```sh
gh issue list --milestone "M3 · Preview, diff & dry-run" --state open
git log --oneline -20
```

Milestones M0–M16 map to the phases in [docs/roadmap.md](docs/roadmap.md). Each milestone has an epic
issue (#1–#17) and the work items reference it with `Part of #N`.

## Orientation

The four planes of [docs/architecture.md](docs/architecture.md) are visible in the tree, and the
boundaries between them are load-bearing:

| Path | Plane | Notes |
|---|---|---|
| `internal/model/` | authoring | Project / Application / Environment types, validation, `schema/*.json` generated by `internal/schemagen` |
| `internal/renderer/` | rendering | **pure**: `(spec, ClusterProfile) → manifests`. `Manifest` is an ordered `*yaml.Node`, never a Go map |
| `internal/delivery/` | delivery | adapter interface plus `direct/`, `flux/`, `git/`, `eject/`, `statemachine/`; `argocd/` is removed (#138, ADR-0012) — the seam stays pluggable and an Argo adapter may return as a follow-up |
| `internal/observation/` | observation | status readback |
| `internal/clusterprofile/` | — | capability detection; what the renderer is told about the target cluster |
| `cmd/kelson`, `cmd/kelson-server` | — | CLI and server |
| `ui/` | — | `kelson-ui`: TypeScript/React web UI (M6). Vite + ConnectRPC clients generated into `ui/src/gen` by `make proto`; see [ui/README.md](ui/README.md) |

Start by reading the package doc comment of the package you're changing. They are written to explain
*why* the boundary exists and they cite issue numbers — `internal/delivery/delivery.go` is the model
for the house style.

Design decisions live in [docs/adr/](docs/adr/). A change that contradicts an accepted ADR is a design
discussion, not a code change: open an issue instead.

## Traps

**The depguard allow-lists are per-plane, and adding a dependency means editing `.golangci.yml`.**
The `main` rule allows only stdlib, `github.com/dafrie/kelson`, `jsonschema`, `cobra` and `yaml.v3`.
`internal/delivery/**` gets a wider list including the Kubernetes clients. A new package outside
`internal/delivery` that imports anything else builds locally and fails CI on lint. Check the rule set
before reaching for a library.

**Renderer purity is enforced mechanically, including against `os`, `io` and `time`.** The deny entries
are anchored with `$` (`os$`, not `os`) because depguard treats bare entries as prefixes; `regex:`
entries cannot be used at all — they make golangci-lint panic. Don't "simplify" that config.

**Golden files are an assertion, not a cache.** If a change updates files under `testdata/`, the
rendered output changed for unchanged input. Say so explicitly in the PR body — it is reviewed as a
behaviour change.

**CI has a docs-only fast path.** Changes touching only `*.md`, `docs/` and `website/` skip lint,
test, build and vulnerability scanning. A change that mixes docs and Go runs everything.

**The docs site reads `docs/` in place.** `website/` is a Docusaurus site whose content is the
markdown under `docs/` — nothing is copied or synced, so `docs/` stays the canonical location. A new
page there must be added to `website/sidebars.ts` or it will not appear in navigation, and broken
markdown links fail the site build. See [website/README.md](website/README.md).

## Parallel agents

Multiple agents often work this repo at once. The protocol:

- **One worktree per agent.** `git worktree add -b ag/<slug> ../kelson-wt-<slug> main`. Never two
  agents in the same working directory.
- **Branch naming is `ag/<letter>-<topic>`** (`ag/g-direct`, `ag/k-eject`), one branch per coherent
  slice of work, and the branch merges to `main` through a PR.
- **Package ownership is exclusive for the life of a task.** A task prompt names the packages you own;
  stay inside them. If your work needs a change in someone else's package, stop and report it rather
  than editing across the boundary.
- **Shared types at an integration seam are agreed before work starts, not invented twice.** When two
  tasks meet at a common type, the orchestrator fixes the contract up front and both sides receive it
  byte-identical. If the contract looks wrong, stop and say so — do not change it unilaterally.
- **Push your branch and open a PR when the work is coherent.** If the PR is low-stakes — docs,
  tracker alignment, mechanical cleanups, changes with no behaviour impact — merge it yourself once CI
  is green. If it changes behaviour, golden files, a public contract or an ADR-governed decision, ask
  for review instead of merging. When in doubt, it is not low-stakes.

## Close the issue when the work lands

This project has repeatedly finished and merged work while leaving its issues open, because the session
doing the work hit a limit before it could tidy up. The result was a tracker that disagreed with `main`
across two whole milestones.

When work merges, close the issue with a comment naming the commit and the files that satisfy each
acceptance criterion. When work is only *partly* done, leave the issue open and comment what remains —
a half-finished issue that looks finished is worse than an open one.
